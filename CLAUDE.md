## Recent changes (August 11, 2026 — logo redesigned: real texture instead of hand-drawn cartoon)

Willis: "the fallboard decal idea is right but it looks completely fake and cartoonish." He reviewed six directions and chose to keep the **fallboard circle**, rejecting the rest outright.

1. **Why the old one read as fake** (worth remembering — the same three mistakes recur): (a) wood grain drawn as ~25 hand-authored squiggly `<path>` curves — real grain is thousands of fine streaks; (b) gold as a 5-stop linear gradient, which reads as video-game treasure rather than gold leaf; (c) a thick uniform black outline around everything, which is a cartoon convention. Glossy key highlights compounded it.
2. **New renderer is Python + numpy/PIL, not SVG.** SVG `feTurbulence` would have been the natural tool but **nothing in the sandbox rasterizes SVG filters** — cairosvg ignores `<filter>` entirely and ImageMagick delegates to rsvg with the same result, so filter output cannot be visually verified before shipping. Textures are therefore generated procedurally and shipped as PNG. Source lives in `branding/logo/options/_source/` (`jwplib.py` path-flattening + masks + anisotropic noise, `mat.py` wood/gold/engrave/emboss materials, `final.py` the shipped mark, `typeface.py` + `tsheet.py` the letterform comparison).
3. **Wood** = layered anisotropic noise (blur wide horizontally, tight vertically → streaks), domain-warped per column so grain waves instead of running dead straight, plus sparse dark pore lines, a lacquer sheen and an edge vignette. **Gold** = flat antique tone with leaf mottle and ~9% wear specks, sitting on a soft drop shadow so it reads as a transfer applied *to* the wood.
4. **Letterforms changed from Libre Baskerville to Century Schoolbook** (`C059-Bold.otf`, URW base35). Willis picked it from a 9-face comparison (`branding/logo/options/_compare-typefaces.png`). Thicker strokes survive shrinking better. The old Baskerville JWP outlines are still extractable from `jwp-logo-circle-rosewood.svg` and are cached at `_source/subs.json` (subpath 0 = J, 1 = W, 2+3 = P).
5. **Proportions per Willis's feedback**: keyboard starts at `CY + 0.131·S` (was far lower), sharps run **72%** of the visible white-key depth (were stubs), 10 white keys instead of 8, decal enlarged to `0.218·S` cap height, wood darkened and de-orangified.
6. **Files replaced** — `client/public/`: `jwp-logo-fallboard.png` (new, 576px, replaces `jwp-logo-rosewood.svg`), `icon-512.png`, `icon-192.png`, `apple-touch-icon.png`, `favicon.png`. Masters at 2000px in `branding/logo/jwp-logo-fallboard{,-compact}.png`. **The old `jwp-logo-rosewood.svg` is still in `client/public/` and is now unreferenced** — safe to delete.
7. **The favicon is a deliberately different render.** Below ~32px the full mark is a brown smudge (the old one was too). `FINAL_compact` uses 6 wide keys, a bigger and brighter decal, and less wear; it feeds `favicon.png` / `apple-touch-icon.png` / `icon-192.png`. `index.html` now declares a 64px `favicon.png` alongside the 512 so browsers pick the legible one — previously `icon-512.png` was the only favicon and got downscaled to mush.
8. **Manifest icons are `purpose: "any maskable"`**, so `icon-192/512` are rendered full-bleed on `#1c140f` with the art inset to 78% — a transparent or edge-to-edge icon gets cropped by Android's mask.
9. **Verified**: full `tsc --noEmit` clean (rsync to `/tmp` with `node_modules` symlinked, ~40s), and every output inspected visually at 144/64/32/20px on light and dark grounds (`branding/logo/options/_compare-small-sizes.png`).

## Recent changes (August 5, 2026 — white-screen crash when editing a client address + app-wide error boundary)

Willis: "when I type in an address to update a client's address (Will Cooper's Newton home) it stops and turns the page completely white."

1. **Root cause: a stale field name in `address-search.tsx`, NOT a Google Maps/API problem.** The July 6, 2026 migration to **Places API (New)** changed the autocomplete response — `server/routes.ts` now maps suggestions to `{place_id, description, mainText, secondaryText}`. The **legacy** Places API returned `structured_formatting: {main_text, secondary_text}`, and `address-search.tsx` still rendered `pred.structured_formatting.main_text`. That property is `undefined` on every live response, so the moment the suggestion dropdown tried to render, React threw `Cannot read properties of undefined (reading 'main_text')`. Reproduced verbatim against the real server shape. **The July 6 CLAUDE.md note claiming "same response JSON shapes as before, so `address-search.tsx` keeps working untouched" was wrong** — `book.tsx` was updated to `mainText`/`secondaryText` at the time, `address-search.tsx` was not. `book.tsx`'s own address box never broke, which is why this went unnoticed for a month.
2. **Why the whole page went white (the second, bigger bug): the app had NO error boundary anywhere.** React's documented behavior is to unmount the *entire* component tree when a render error reaches the root uncaught — hence a blank page rather than a message. Any future render bug anywhere would have done the same thing.
3. **`address-search.tsx` fixes**: `Prediction` now declares `mainText`/`secondaryText` **and** tolerates the legacy `structured_formatting` shape, with **every field optional**; two module-level helpers `predMainText`/`predSecondaryText` resolve new-shape → legacy-shape → `description` → `""`, so a missing field can never throw again. Also hardened: autocomplete fetch checks `r.ok` and filters predictions lacking `place_id`; `handleSelect` checks `res.ok` before using the body (a failed `/details` returns `{error}`, which used to be spread into the form as undefined) and coerces every field with `?? ""`; both fetches gained `credentials: "include"` (matches the rest of the app); a new `lookupFailed` state renders an inline red "type it into the fields below instead" hint rather than failing silently.
4. **New `client/src/components/error-boundary.tsx`** — class component (`componentDidCatch` has no hook equivalent): friendly card with the error message, **Try again** (resets state) and **Go to dashboard** buttons, full stack logged to the console. Wired into `App.tsx` **inside** the keyed `motion.div` so navigating to another page remounts and auto-resets it, and the sidebar/header stay usable when a page crashes; `/book` gets its own boundary (`area="the booking page"`).
5. **Verified**: full-project `npx tsc --noEmit` clean **and** a `client/src/**` + `shared/**` scoped run clean (both from a `/tmp` copy with `node_modules` symlinked). Plus 5 runtime assertions on the extracted helpers covering the live server shape, the legacy shape, description-only, empty, and null-ish fields — all pass, and the same test confirms the OLD code threw on real live data.
6. **Frontend-only — no restart, no `db:push`.** Vite HMR picks it up; a browser refresh is enough. Commit + push to reach the deployed site.
7. **Lesson worth keeping**: when a server response shape changes, grep for **every** consumer of the old field names before declaring callers unaffected. `grep -r "structured_formatting" client/` would have caught this in one second on July 6.

Plain `node <file>.mjs` (no TS/no transform) and `npx tsc --noEmit` (pure TS type-checker, no native binary involved) both work fine anywhere. **Practical rule: write standalone scripts as plain `.mjs`, not `.ts`, if they might ever run outside Willis's own Mac terminal** (e.g. from a scheduled task). `scripts/cfo-snapshot.mjs` exists specifically because of this.
- **`npm run db:push` must be run by Willis himself**, in his own Mac Terminal, after any `shared/schema.ts` change — it cannot be run from a remote/sandboxed session for the reason above.
- **File deletion in the connected project folder can be gated above normal Unix permissions** — `rm` may fail with "Operation not permitted" even when `ls -la` shows correct ownership. If that happens, use the `mcp__cowork__allow_cowork_file_delete` tool (request permission for the specific path) rather than concluding deletion is impossible.
